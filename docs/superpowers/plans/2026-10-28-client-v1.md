# Клиент AIIRISDX v1: план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Серверный клиент, принимающий эндоскопическое видео (WebRTC или файл), прогоняющий его через YOLO-каскад и дающий вторичный экран с точно совпадающими bbox и контейнер «видео + JSON-лог».

**Architecture:** Браузер у стойки присваивает кадру идентификатор, пишет чистое видео локально и шлёт копию по WebRTC. Сервер (FastAPI + aiortc) читает идентификатор, ставит кадры в ограниченную очередь пула GPU-воркеров и возвращает результаты по WebSocket с тем же идентификатором. Клиент показывает кадр с задержкой, только вместе с его результатом. Модели — подключаемые стадии единого интерфейса.

**Tech Stack:** Python 3.12, FastAPI, aiortc/av, Celery/Redis (только фоновые задачи), Ultralytics YOLO, pydantic, pytest; React 18 + Vite + TypeScript, vitest; Docker/docker-compose, coturn.

**Spec:** `docs/superpowers/specs/2026-10-28-client-design.md` (далее «спека», §N — её разделы). Референс UI/логики: `/mnt/work-disk/Documents/Dev/video_stream_client/video_stream_project` (далее «прототип»). Платформа обучения (не меняется в этом плане): `/mnt/work-disk/Documents/Dev/endoscopy-platform`.

## Global Constraints

- Сквозная задержка вторичного экрана ~1 с, размер буфера выравнивания настраивается (§8а).
- Вход 1080p30; 4K сжимается до рабочего разрешения инференса, bbox в логе хранятся в системе исходного кадра (§3, §4, §8а).
- Лог: JSONL, версионированная схема, деперсонализирован; сохранённое видео H.264 MP4 без запечённых рамок, пишется локально у стойки (§6).
- Идентификатор сессии: номер стойки + дата-время + UUID. Авторизации нет; защита — токен стойки + TLS, включается настройкой (§3).
- Стек: FastAPI, aiortc, Celery/Redis, React. Долгоживущие потоки не ставятся в Celery (§8а).
- Linux, NVIDIA GPU, Docker, работа без интернета; TURN в поставке (§3, §8а).
- Лицензия — AGPL-совместимая; Ultralytics используется напрямую (§3).
- Не входит: пользователи/пациенты, голос, постобработка, сегментация (заглушка), DICOM, RT-DETR, DINOv3, плеер (§8).
- Ограничение среды: каталог не git-репозиторий; Task 0 делает `git init`.

## Review Focus

1. Перегрузка очереди: кадр пропущен — на экране он без рамок, никогда с чужими.
2. Обрыв связи с сервером посреди сессии: локальная запись продолжается, контейнер собирается с пометкой «лог неполный».
3. Результаты приходят не по порядку, с повтором или после таймаута: рамки не должны подставляться другому кадру.
4. Кадрирование включено или изменено: bbox в логе остаются в системе исходного кадра.
5. Видеофайл нулевой длины, битый или оканчивающийся посреди кадра; 4K-вход с масштабированием.

(каждая строка закреплена тестом в задаче-владельце, см. помеченные «RF1…RF5»)
