# Известные ограничения и что проверить на реальной стойке (v1)

Составлено по итогам выполнения плана `docs/superpowers/plans/2026-10-28-client-v1.md`.

## Не проверено на реальном оборудовании

- Реальная карта захвата и эндоскопическое видео: читаемость метки кадра, доля кадров, дошедших до сервера (в headless Chrome с синтетикой кодировщик пропускал 13–28 % штампованных кадров; без подсказок по битрейту на детальном 1080p — почти все). Страница для проверки: `frontend/capture-check.html`.
- Запись через OPFS, всплывающее окно вторичного экрана, звук сигнала.
- TURN-ретрансляция и облачная схема (токен стойки + TLS); запрет ретрансляции в частные сети задан только конфигурацией `deploy/coturn.conf`, живой проверки не было.
- Классификаторы (зона, качество, режим) не обучены: пайплайн работает на заглушке.

## Заглушки и допущения

- `backend/app/pipeline/stages/anatomy_rules.yaml` — **примерный набор, не клинические правила**. Связи прототипа лежат только в БД Django; нужны выгрузка или правила от врачей. Словарь зон реального классификатора неизвестен.
- Сегментация, постобработка, голос, DICOM, RT-DETR, DINOv3 — вне v1.

## Не реализовано из спецификации (§8а)

- Режим «Видеофайл на сервере» по-прежнему ничего не показывает в браузере (работает через API, лог и контейнер). Выбор файла с компьютера и вторичный экран закрыты режимом «Видеофайл с этого компьютера» (файл играет в браузере и идёт через тот же конвейер, что камера); его ограничения: ширина кадра файла не меньше 640 px (метка номера кадра), файл целиком в памяти браузера.
- Камера, пропавшая посреди сеанса, не возобновляется в том же сеансе (счётчик кадров обнулился бы): сеанс останавливают и начинают новый; врач видит сообщение «сигнал потерян».
- Оформление страницы стойки переведено на цвета и шапку референса; остальные экраны референса (пациенты, протоколы, галереи находок, боковое меню, голос) не переносились.
- Хранилище S3, сроки хранения, API выдачи файлов (решение R11): только локальный `sessions_dir` и `GET /sessions/{id}/log`.

## Производительность

- Замер: 4 потока 1080p30 на одну RTX 2070 с 2 воркерами (пропусков 0 %, p95 19 мс). Замер без WebRTC/RTP, без чтения метки и без классификаторов, поэтому реальное N ниже (`tests/load/README.md`).
- Копирование кадра в пул ограничивает пул примерно 120 кадрами в секунду.

## Отложенные замечания ревью (мелкие)

Полный список в истории коммитов и отчётах задач; главные группы: устойчивость пула (watchdog на зависший кадр, перезапуск воркера, упавшего сразу после готовности), гонка реапера простаивающих сессий с `/stop`, неограниченная очередь записи лога, рекордер (очистка OPFS, лимит памяти без OPFS), мелкие замечания по буферу выравнивания (`gapGraceMs` не из профиля).
